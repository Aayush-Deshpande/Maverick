4.1 Multi-Mode 3D Engine Viewport & FLIR Pyrometry (UX-01, D71)
----------------------------------------------------------------------------------------------------
Files:
  - `frontend/src/utils/engineShaders.ts`
  - `frontend/src/utils/engineComponents.ts`
  - `frontend/src/components/viewer3d/EngineViewer3D.tsx`
  - `frontend/src/components/viewer3d/ThermalLegend.tsx`
  - `frontend/src/tests/engineShaders.test.ts`
  - `frontend/src/tests/engineComponents.test.ts`

Methodology & Algorithms:
The 3D canvas operates in four real-time modes while preserving 60 FPS rendering:
  1. Solid CAD Surface (`solid`):
     Restores authentic aerospace PBR materials: cast aluminum crankcase, anodized blue valve covers
     (Rotax 915 iS), heat-tinted stainless steel exhaust runners, and black powder-coated intake plenums.
  2. Physical X-Ray Glass (`glass`):
     Casing and valve cover meshes are dynamically mutated into Three.js `MeshPhysicalMaterial`:
       - `roughness`: 0.12
       - `metalness`: 0.05
       - `transmission`: 0.92 (real physical optical transmission)
       - `ior`: 1.48 (borosilicate optical glass index of refraction)
       - `thickness`: 0.8
       - `clearcoat`: 1.0, `clearcoatRoughness`: 0.1
       - `transparent`: true, `opacity`: 0.35, `depthWrite`: false
     Internal mechanical assemblies (pistons, connecting rods, crankshaft, valves) remain opaque PBR,
     creating a photorealistic look revealing the reciprocating internals.
  3. Dynamic FLIR Thermal Pyrometry (`thermal`):
     - Background casing is rendered in non-emissive smoked obsidian glass (`transmission: 0.85`,
       `color: #1a1a24`).
     - Live thermodynamic telemetry (CHT 1..4, EGT 1..4) is mapped to cylinder and exhaust meshes.
     - Color Ramp Formula:
         * CHT Normalized: t_cht = clamp((cht_c - 50) / 90, 0, 1)  [50°C to 140°C]
         * EGT Normalized: t_egt = clamp((egt_c - 400) / 550, 0, 1) [400°C to 950°C]
         * Blackbody Incandescence Spectrum:
             t = 0.00: Deep Indigo/Purple (#1e085a)
             t = 0.25: Royal Blue (#1038a6)
             t = 0.50: Cherry Red (#b01a24)
             t = 0.75: Radiant Amber-Orange (#e66412)
             t = 1.00: Incandescent White-Yellow (#fff275)
     - Materials receive `emissive` color with intensity proportional to temperature, accompanied by
       the floating `ThermalLegend.tsx` HUD showing live CHT readouts per cylinder.
  4. Twin Ghost (`ghost`):
     Nominal twin holographic wireframe/additive overlay (`blending: AdditiveBlending`, `opacity: 0.45`)
     enabling instant visual departure detection between nominal model and degraded engine.

Fault Highlight Precedence Rule:
Whenever an injected fault or diagnostic anomaly triggers on a component, its material is immediately
promoted to alert highlights (Red = Critical, Amber = Caution, Violet = Injected), overriding the base
shader mode.

Methodology & Algorithms:
  1. Zero-Lag Telemetry Grounding:
     Instead of polling SQL databases or running disk queries, the copilot accesses engine state
     directly from the in-memory simulation channel in RAM (`ServicesSource.state()` resolving via
     `services.channel(engine_id).last_message`). Latency is < 0.1 ms with zero disk I/O.
  2. Non-Blocking Event-Driven Async Worker:
     Whisper STT transcription, LLM response generation, and Kokoro TTS audio synthesis are
     offloaded to threadpool workers via `asyncio.to_thread`. This guarantees that the 20 Hz WebSocket
     telemetry broadcast loop to the GCS cockpit is never interrupted or jittered.
  3. Dynamic LLM with Offline Emergency Fallback:
     Removed early demo hardcoded intercepts. The copilot dynamically synthesizes telemetry, FMECA
     diagnostics, and OEM manual citations. If the LLM service is offline or unreachable, deterministic
     ATA-coded emergency checklists execute as an offline fallback.
  4. DRDO Military Voice Bearing:
     Voice responses follow strict operational rules: action-first direct statements, plain spoken
     sentences without markdown formatting, and refusal guardrails rejecting non-aviation queries.
  5. UI Loaders:
     Animated SVG spinners, skeleton placeholder cards, and in-transcript live thinking token streaming.

4.3 Virtual CAN Bus & FADEC J1939 Telemetry Link (M7-01, M7-02, M7-04, D72)
----------------------------------------------------------------------------------------------------
Files:
  - `backend/sources/can_link.py`
  - `backend/runtime/engine_runtime.py`
  - `backend/runtime/hub.py`
  - `backend/server/api_v1.py`
  - `frontend/src/components/CanBusInspector.tsx`
  - `tests/can/test_can_endpoints.py`

Methodology & Algorithms:
  1. Dynamic Runtime Source Hot-Swapping:
     `EngineRuntime` supports switching between `DIRECT` (continuous differential equation solution)
     and `CAN` (quantized FADEC J1939 link) on the fly without restarting the simulation worker or
     re-calibrating thermodynamic states (`POST /api/v1/runtime/source`).
  2. SAE J1939 Frame Matrix:
     Telemetry is formatted into 6 standard 29-bit extended arbitration frames:
       - 0x18FF1000 (ENG_SPEED_TORQUE): RPM, Torque, Throttle, 4-bit sequence counter (100 Hz / 10ms)
       - 0x18FF1001 (ENG_PRESSURES): MAP, Oil Pressure, Fuel Rail Pressure (50 Hz / 20ms)
       - 0x18FF1002 (ENG_TEMPERATURES): CHT 1..4, EGT 1..4, Coolant Temp (20 Hz / 50ms)
       - 0x18FF1003 (ENG_FLUIDS): Oil Temp, Fuel Flow rate, Ambient Temp (10 Hz / 100ms)
       - 0x18FF1004 (ENG_ELECTRICAL): Bus Voltage, Alternator Current, ECU Lane Status (10 Hz / 100ms)
       - 0x18FF1005 (ENG_DYNAMICS): 0.5X, 1X, 2X, Gear-mesh Vibration Orders (50 Hz / 20ms)
  3. Real-Time CAN Intrusion Detection System (CAN IDS):
     A sliding window analyzes frame arrival intervals, sequence continuity, and payload ranges:
       - Unknown / Rogue Arbitration IDs: Flags unauthorized ECUs or bus taps (e.g. `0x18FF99FF`).
       - Sequence Counter Discontinuity: Flags dropped frames or replay attacks (+5 sequence jump).
       - Out-Of-Range Payloads: Flags corrupted or spoofed sensor signals exceeding DBC limits.
     Security alerts are logged and verified against the SHA-256 Merkle-tree flight data ledger.

       steady-state calibration. Transitions to HTTP 200 `{"ready": true, "engines_calibrated": 5}`
       once all 5 engines are ready to accept traffic.
