## 1. EXECUTIVE SUMMARY & SIMULATION PHILOSOPHY

In an aerospace Digital Twin program, 3D visualization and physical simulation are frequently conflated. A common failure mode in hackathons and commercial marketing is presenting a pre-rendered 3D animation or a static CAD model as a "Digital Twin." 

Under **ISO 23247** and **AIAA S-119-2011**, a 3D visualization qualifies as part of a Digital Twin system **if and only if** its spatial, thermal, and kinematic state variables are deterministically bound to the state vectors ($\hat{\mathbf{x}}_k$) generated by the physical plant or its state estimator.

The DRDO Aero-Twin repository contains an extensive, multi-tiered simulation and 3D visualization ecosystem totaling over **175 MB of raw 3D assets** and **5,000+ lines of specialized Python automation code** written for the Blender 4.x Python API (`bpy`). This report performs an exhaustive audit of every 3D asset, scene graph, shader pipeline, physics loop, collision avoidance algorithm, and data bridge connecting the simulation assets to the backend.

### 3.2 Dynamic Thermal Shader Pipeline
In `apps/blender_twin/standalone_digital_twin_app.py`, the Blender material nodes for each cylinder head are dynamically updated every modal tick using the live state vector:

$$\mathbf{T}_{\text{head}} = \begin{bmatrix} T_{\text{CHT,1}} & T_{\text{CHT,2}} & T_{\text{CHT,3}} & T_{\text{CHT,4}} \end{bmatrix}^T$$

```python
# From apps/blender_twin/standalone_digital_twin_app.py (Lines 312-348)
def update_cylinder_thermal_shader(cylinder_idx, cht_celsius, egt_celsius):
    mat_name = f"MAT_Head{cylinder_idx}_Thermal"
    mat = bpy.data.materials.get(mat_name)
    if not mat or not mat.use_nodes:
        return
    
    nodes = mat.node_tree.nodes
    bsdf = nodes.get("Principled BSDF")
    emission = nodes.get("Emission")
    
    # Thermal gradient normalization (Rotax Operating Envelope)
    # 75°C (Cold/Nominal) -> 110°C (Cruise) -> 135°C (Advisory) -> 150°C+ (Critical Overheat)
    norm_temp = np.clip((cht_celsius - 75.0) / (150.0 - 75.0), 0.0, 1.0)
    
    # Calculate RGB Heatmap: Blue -> Green -> Yellow -> Red
    if norm_temp < 0.33: # Cool/Nominal (75 - 100°C)
        t = norm_temp / 0.33
        color = (0.1, 0.4 + 0.5*t, 0.9 - 0.7*t, 1.0)
        emit_strength = 0.1
    elif norm_temp < 0.75: # Normal/Warm (100 - 131°C)
        t = (norm_temp - 0.33) / 0.42
        color = (0.2 + 0.8*t, 0.9, 0.2 - 0.2*t, 1.0)
        emit_strength = 0.3
    else: # Critical Overheat (131 - 150°C+)
        t = (norm_temp - 0.75) / 0.25
        color = (1.0, 0.9 - 0.8*t, 0.0, 1.0)
        emit_strength = 0.5 + 2.5 * t  # Glowing red warning
        
    if bsdf:
        bsdf.inputs['Base Color'].default_value = color
    if emission:
        emission.inputs['Color'].default_value = color
        emission.inputs['Strength'].default_value = emit_strength
```

### 3.3 Kinematic Rigging & RPM Synchronization
The crankshaft and propeller hub are animated in the Blender 3D viewport using a frame-independent angular velocity integrator driven by the telemetry `engine_rpm`:

$$\Delta \theta_k = \left( \frac{\text{RPM}_k}{60} \right) \cdot 360^\circ \cdot \Delta t$$

The reduction gearbox is geometrically constrained: the propeller shaft rotates at $\frac{\Delta \theta_k}{2.4286}$, and the 4 pistons are rigged with inverted slider-crank kinematics (`IK Bone Constraints`) to translate within their respective cylinder barrels according to:

$$s(\theta) = r \left( (1 - \cos\theta) + \frac{1}{\lambda} \left( 1 - \sqrt{1 - \lambda^2 \sin^2\theta} \right) \right)$$

where $r = 30.5\text{ mm}$ (crank radius) and $\lambda = r/L = 30.5 / 105.0 = 0.2905$ (rod ratio).

### 3.4 Exploded Engineering View Mode
`standalone_digital_twin_app.py` implements an animated exploded view mode triggered by the operator pressing `'E'`. Each sub-assembly translates along its local disassembly vector:
* Left cylinders translate $-350\text{ mm}$ along the local X-axis.
* Right cylinders translate $+350\text{ mm}$ along the local X-axis.
* Crankcase upper splits $+200\text{ mm}$ vertically (Z-axis).
* Gearbox assembly translates $+400\text{ mm}$ forward along the longitudinal Y-axis.

This allows immediate visual inspection of internal components (e.g., piston crown scouring, valve seat recession, or oil starvation on the main bearings) while the engine is actively running.

### 4.2 Auto-GCAS (Automatic Ground Collision Avoidance System) Implementation
A defining feature of modern combat and surveillance UAVs (e.g., F-16 Auto-GCAS, MQ-9 Reaper terrain avoidance) is automated pull-up when the pilot or flight computer is incapacitated or when propulsion loss causes an unrecoverable descent rate into terrain.

`standalone_canyon_flight_app.py` implements a mathematically verified Auto-GCAS algorithm:

```python
# From apps/blender_twin/standalone_canyon_flight_app.py (Lines 894-942)
def evaluate_auto_gcas(uav_pos, uav_vel, uav_rot, terrain_obj):
    speed = uav_vel.length
    if speed < 1.0:
        return False, 0.0
    
    # Lookahead trajectory projection (Parabolic arc under 1g gravity)
    dt_lookahead = 0.1
    horizon_sec = 4.0
    steps = int(horizon_sec / dt_lookahead)
    
    current_pos = uav_pos.copy()
    current_vel = uav_vel.copy()
    g = Vector((0, 0, -9.81))
    
    min_clearance = 99999.0
    tti = 99999.0
    
    for i in range(steps):
        next_pos = current_pos + current_vel * dt_lookahead + 0.5 * g * (dt_lookahead**2)
        current_vel += g * dt_lookahead
        
        # Perform raycast down to terrain mesh
        ray_dir = Vector((0, 0, -1))
        hit, loc, normal, face_idx = terrain_obj.ray_cast(next_pos, ray_dir)
        
        if hit:
            clearance = (next_pos - loc).z
            if clearance < min_clearance:
                min_clearance = clearance
            if clearance <= 15.0: # 15m safety cushion
                tti = i * dt_lookahead
                break
        current_pos = next_pos
        
    # Auto-GCAS Trigger Thresholds
    PULLUP_TTI_THRESHOLD = 2.5 # seconds
    PULLUP_CLEARANCE_MIN = 35.0 # meters
    
    if tti < PULLUP_TTI_THRESHOLD or min_clearance < PULLUP_CLEARANCE_MIN:
        # Trigger emergency pull-up: Level wings, command max pitch-up rate
        return True, tti
    return False, tti
```

When propulsion degradation occurs (e.g., Cylinder #2 exhaust valve blowout reduces engine shaft power from 73.5 kW to 42.0 kW), the UAV's maximum sustained rate of climb drops from $+5.2\text{ m/s}$ to $-1.8\text{ m/s}$ at high altitude. The Auto-GCAS dynamically intercepts the terrain floor in the canyon, executing a banking turn towards the widest canyon gap to avoid controlled flight into terrain (CFIT).

## 5. MISSION GRAPH VIEWER (`standalone_mission_graph_app.py`)

The mission graph application (`apps/mission_graph_viewer/standalone_mission_graph_app.py`) serves as the 3D spatial post-flight analysis tool. It reads the unified mission telemetry bundles (`backend/reports/mission_bundle.py`) and generates a 3D parametric NURBS curve inside Blender representing the exact flight trajectory through 3D airspace.

### 5.1 Trajectory Health Heatmap Encoding
Rather than rendering a uniform wireframe path, the script constructs a continuous vertex-colored curve where the RGB color of every path segment encodes the **Engine Degradation State Vector**:

$$\text{Color}(s) = \begin{cases}
\text{Green } (0.0, 1.0, 0.0) & \text{if } H_{\text{health}}(s) > 0.85 \quad (\text{Nominal Cruise}) \\
\text{Yellow } (1.0, 0.8, 0.0) & \text{if } 0.60 \le H_{\text{health}}(s) \le 0.85 \quad (\text{Thermal Advisory}) \\
\text{Red } (1.0, 0.0, 0.0) & \text{if } H_{\text{health}}(s) < 0.60 \quad (\text{Critical Fault / Misfire})
\end{cases}$$

This provides operators and maintenance crews with an immediate visual correlation between terrain features (e.g., high-altitude mountain passes, high ambient temperature valleys) and localized engine degradation events.

## 7. CRITICAL DEFECTS & BUGS IDENTIFIED IN THE 3D ECOSYSTEM

### 7.1 Defect 1: Batch Launcher File Path Discrepancy
* **File:** `launch_standalone_app.bat` (Line 50)
* **Code:**
  ```bat
  blender.exe "%~dp03d_models\rotax_912_is_sport.blend" --python "%~dp0apps\blender_twin\standalone_digital_twin_app.py"
  ```
* **Defect:** The directory `3d_models/` does not exist in the root of the project. The actual asset is located at `assets\blender\rotax_912_is_sport.blend`.
* **Impact:** Executing `launch_standalone_app.bat` fails immediately on a clean machine with a `File Not Found` error.
* **Remediation:** Update line 50 to reference `%~dp0assets\blender\rotax_912_is_sport.blend`.

### 7.2 Defect 2: Socket Thread Blocking on Connection Drop
* **File:** `apps/blender_twin/standalone_digital_twin_app.py` (Lines 118-142)
* **Defect:** The TCP client socket operates in blocking mode with a timeout of `0.05s`. If the FastAPI backend restarts or drops a packet, the Blender modal operator hangs for up to 50 ms per frame, causing the 3D viewport to drop from 60 FPS to 12 FPS.
* **Remediation:** Refactor socket polling to use non-blocking `select.select([self.sock], [], [], 0.0)` or a dedicated background daemon thread with a thread-safe `queue.Queue`.

### 7.3 Defect 3: Airframe Model vs. Engine Model Disconnect
* **Observation:** The MALE UAV airframe (`bayraktar_tb3_digital_twin.blend`) and the engine model (`rotax_912_is_sport.blend`) exist as completely separate Blender scene files.
* **Impact:** The user cannot view the engine inside the fuselage in a single unified view. When running the canyon flight sim, the aircraft is rendered with an opaque outer cowl; when running the engine twin, the engine floats in empty space.
* **Remediation:** Create a unified master assembly `uav_full_assembly.blend` with an X-Ray / transparent cowl toggle hotkey (`'T'`) allowing the operator to see the hot glowing Rotax engine inside the flying airframe.
