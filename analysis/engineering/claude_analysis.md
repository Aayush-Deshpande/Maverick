Response synthesis is 100% deterministic templating: directive → formatted checklist string; else top retrieved chunk → formatted; else a canned "nominal" message.
So: diagnostic_agent.py = rule-based ATA knowledge base/reasoner (used directly by Plane 1's server too). copilot.py = the conversational wrapper (guardrails + retrieval + diagnostic lookup + templated NL response), with an LLM hook that is present in name only.

1. backend/server/main.py — FastAPI hub
   App: FastAPI(title="Rotax 912 iS MALE UAV Digital Twin Server", version="2.0.0", lifespan=lifespan). CORS wide open (allow_origins=["*"]).
   Startup (lifespan): calls EngineStateService.get_instance() (creates singleton, which starts its own 20 Hz worker thread), then spawns an asyncio task broadcast_telemetry_loop(service). On shutdown, cancels that task.
   broadcast_telemetry_loop: every 0.05s (20 Hz), pulls service.get_latest_state(), serializes with model_dump_json(), fans out to two independent socket pools: active_web_sockets and active_blender_sockets, pruning dead sockets on send failure.
   REST endpoints:
   GET / — service banner + endpoint map.
   GET /api/health → ServerHealthResponse (sortie id, engine running, active fault, client counts, 20 Hz).
   GET /api/state → UnifiedTelemetryState snapshot (service.get_latest_state()).
   POST /api/control — body is ControlCommand; delegates to service.handle_command(cmd); raises HTTPException(400) on ERROR status.
   POST /api/debrief — triggers service.export_debrief() (CBM post-flight report).
   WebSocket endpoints:

2. backend/server/engine_service.py — the orchestrator
   EngineStateService is a thread-safe singleton (get_instance() guarded by threading.Lock) that IS the authoritative 20 Hz tick loop — confirmed orchestrator role.

State held: sortie*id, is_engine_running, throttle_pct, altitude_ft, oat_c, region, flight_phase, commanded fault (active_fault_id, fault_severity, fault_start_time), plus wired subsystems: thermo_model (RotaxThermoModel), streamer (TelemetryStreamer), score_buffer (ScoreBuffer), pipeline (DetectionPipeline, with load_models() called at init), prognostics (PrognosticsWorker, interval_sec=20.0, planned_mission_hours=18.0), graph (MissionKnowledgeGraph), reporter (MissionReporter), agent (DiagnosticAgent). Note: engine_service.py additionally pulls in Plane-2-adjacent modules not in the requested file list — backend/agent/diagnostic_agent.py (DiagnosticAgent, DiagnosticDirective, ROTAX_ATA_FAULT_DIRECTIVES) and backend/graph/mission_graph.py / mission_reporter.py — these are the ATA-reasoning / knowledge-graph / CBM-report layer that sits directly in the hot path of \_tick().
**init**: starts self.graph.start_sortie(...), self.prognostics.start() (daemon thread), and its own daemon worker thread self.worker_thread = threading.Thread(target=self.\_run_loop, daemon=True) — this is the actual 20 Hz deterministic loop, independent of FastAPI's event loop.
\_run_loop: dt=0.05; each cycle takes self.state_lock, calls self.\_tick(dt), then sleeps max(0.001, dt - elapsed).
\_tick(dt) — full per-frame sequence:
Sync streamer region.
actual, expected, residuals = self.streamer.generate_frame().
If engine off, zero out kinematics/pressures manually; else override RPM/TPS/altitude/OAT/phase from operator-set throttle/altitude/OAT (throttle→RPM linear map 1800–5800 RPM; skips override for fault 3 misfire jitter).
Recompute residuals against the overridden actual: residuals = self.thermo_model.compute_residuals(actual, expected).
Run the 9-stage pipeline: event_diag = self.pipeline.process_frame(actual, self.prev_actual, dt_sec=dt).
Diagnosis precedence logic: if operator commanded a fault (active_fault_id>0) that's authoritative; else use event_diag.ml_detection_payload's primary_fault_id; if that's 0 but residuals.anomaly_score>0.45, it re-runs pipeline.\_spectral.update(...), pipeline.\_sanity.validate(...), pipeline.\_classify(...) directly (bypassing the majority-vote gate) as a fallback classifier.
Pulls an ATA DiagnosticDirective from self.agent.diagnose(diag_fid, confidence=diag_conf) if a fault is active, records it into self.graph (record_anomaly, optionally record_maintenance_action).
Reads self.prognostics.latest_report for Go/No-Go and RUL (defaults rul_p10=14.2, rul_p50=18.0 if no report yet).
Assembles EngineTelemetry + AnalyticsState → UnifiedTelemetryState, stored as self.latest_state.
Command handling handle_command(cmd: ControlCommand): START_ENGINE, STOP_ENGINE, SET_FAULT (validates against DRDO_FAULT_DEFINITIONS, calls streamer.set_fault(fid, severity, ramp_duration_sec=6.0), resets pipeline), CLEAR_FAULT, SET_THROTTLE, SET_ALTITUDE, SET_OAT, SET_REGIME, EXPORT_DEBRIEF. After every command, immediately forces self.\_tick(0.05) for instant feedback.
export_debrief(): computes flight hours from self.graph.sorties[sortie_id].start_timestamp, calls graph.complete_sortie(...), then self.reporter.generate_report(self.graph, self.sortie_id) → returns file path (written under data/mission_reports/ per docstring).

trend_analyser.py — background prognostics (PrognosticsWorker, 20s interval thread) built on ScoreBuffer (thread-safe deque, maxlen=3600 = 3 min at 20Hz — written every frame by the main pipeline). DegradationTrendAnalyser.analyse() fits linear/exponential/power-law models (closed-form OLS, log-transform for exp/power) over 3 window sizes (2/10/30 min), selects by AIC, computes time_to_threshold_min via binary search. ProbabilisticRULEstimator runs 500-sample Monte Carlo perturbation of fitted parameters → p10/p50/p90 RUL in minutes; go_no_go() compares p10 vs planned mission hours ± 2h margin → GO/CAUTION/NO-GO. COMPONENT_CHANNELS maps 6 components to primary residual channels (e.g. Cylinder_Head_Assembly→d_CHT_2). This is the actually-wired prognostics engine (unlike rul_estimator.py).

detection_pipeline.py — DetectionPipeline, the composition point implementing the documented 9-stage pipeline: (1) SensorSanityValidator.validate, (2) RotaxThermoModel.compute_expected_state+compute_residuals, (3) anomaly score = max(ae_score, residuals.anomaly_score) (AE + Z-score fusion), (4) GearboxSpectralAnalyser.update (blended in if higher), (5) write (timestamp, composite_score, per-channel scores) to ScoreBuffer, (6) \_classify() — RF model first (if composite_score > ANOMALY_GATE=0.35), else physics-boundary fallback (excludes sensor-failed channels via sanity.failed_channels), (7) MajorityVoteBuffer (10-frame window, 80% agreement threshold, prevents single-frame false alarms), (8) reads PrognosticsWorker.latest_report if attached via set_prognostics_worker, (9) \_maybe_emit() builds and returns a DiagnosticEvent (30s alert holdoff via \_ALERT_HOLDOFF_SEC) only if a fault is majority-confirmed OR a WATCH/WARNING/CRITICAL trend alert is active. DiagnosticEvent = {timestamp_iso, sortie_id, flight_context, sensor_sanity, ml_detection_payload} — this is the doc02 §3 JSON contract. Internally calls self.\_agent.diagnose(...) (DiagnosticAgent from backend/agent/diagnostic_agent.py) to enrich the payload with ATA chapter, manual reference, checklist, root-cause explanation, maintenance order.

7. backend/telemetry/*.py
   can_streamer.py — DRDO_FAULT_DEFINITIONS (0–8, name/description/target_mesh/severity — the canonical fault catalog reused everywhere). TelemetryStreamer(sample_rate_hz=20.0): get_flight_context(t_sec, region) produces sinusoidal-varying altitude/OAT/TAS/TPS/RPM/phase for LADAKH (18.5k±3.5k ft, cold) vs THAR_DESERT (4.5k±2k ft, hot) vs default cruise. generate_frame() computes expected_state via thermo model, then builds actual_state = expected + Gaussian sensor noise (CHT σ=0.18°C, EGT σ=1.2°C, oil press σ=0.03 bar, RPM σ=12, etc.), then if active_fault_id>0 applies a progressive ramp (ramp = min(1, elapsed/ramp_duration) × severity) with fault-specific coherent multi-parameter perturbations for each of the 8 faults (e.g. F1: CHT_2 += 38*ramp; F3: RPM jitter ±180*ramp + EGT_2 -= 115*ramp; F4: OIL_PRESS *= (1-0.65*ramp)). Returns (actual, expected, residual_vector). generate_flight_log() produces full time-series arrays for CSV export. This is the module EngineStateService directly holds as self.streamer and calls every tick — the CAN-data "source" in the running server is entirely synthetic/simulated (no actual CAN bus hardware interface in this codebase; "CAN streamer" is a naming/documentation choice, not a real bus reader).

dataset_fusion_engine.py — TriSourceDatasetFusionEngine: creates data/telemetry/{source1_avionics_logs, source2_nasa_benchmarks, source3_drdo_missions, fused_master} dirs. generate_all_source3_drdo_sorties() uses TelemetryStreamer.generate_flight_log() to synthesize 2 nominal + 8 fault CSVs (Source 3 = DRDO-simulated). build_fused_master_datasets() ingests Source 1 via GarminG3XParser, Source 3 CSVs directly, computes physics residuals for Source 1 rows, does an 80/20 train/val split, writes master_training_dataset.csv/master_validation_dataset.csv + dataset_manifest.json. Note: Source 2 (NASA) is never actually ingested into the fused dataset — NASABenchmarkParser is imported and instantiated (self.nasa_parser) but build_fused_master_datasets() has no step that reads source2_nasa_benchmarks files or calls self.nasa_parser — manifest still reports a source2_nasa_benchmarks file count (glob'd but unused for feature fusion). This is a real gap in the "tri-source" strategy — only 2 of 3 sources are actually fused.

rotax*dataset_generator.py — RotaxTimeSeriesGenerator: a higher-fidelity generator using proper first-order lag/coupled ODEs (time constants: tau_map=0.15s, tau_rpm=0.40s, tau_ff=0.20s, tau_egt=0.35s, tau_cht=6.5s, tau_oil=35s) rather than the simpler noise-on-baseline approach in can_streamer.py. generate_mission_sortie() supports flight phases (CLIMB/CRUISE_LOITER/DESCENT_RECOVERY), 3 throttle patterns (SMOOTH_LOITER, GUST_TRANSIENTS, STEP_LOITER), coherent per-fault multi-signal injection. generate_partitioned_dataset_suite() builds strictly isolated 10 TRAIN / 10 VAL / 10 TEST missions with deliberately shifted altitude/OAT offsets and seeds per split (to prevent train/test leakage) — outputs already exist on disk (data/telemetry/{train,val,test}/, rotax912*{train,val,test}\_dataset.csv, mission_partition_manifest.json). This generator is independent of (and more sophisticated than) dataset_fusion_engine.py's Source-3 generation — two parallel/overlapping synthetic-data pipelines exist in the repo.

parsers/garmin_parser.py — GarminG3XParser.parse_csv_file(): maps Garmin G3X/G1000 CSV headers (HEADER_MAPPING dict, e.g. "E1 CHT1"→"CHT_1") to canonical fields, auto-detects and converts Fahrenheit→Celsius for CHT/oil temp (if val>150/160: convert), fills missing fields with nominal defaults, assumes 1 Hz Garmin sample rate.

parsers/nasa_prognostics_parser.py — NASABenchmarkParser: parse_cmapss_txt_file() reads NASA C-MAPSS space-separated files (21 sensor channels, limited to max_engines=10). parse_run_to_failure_trajectory() handles both .txt (C-MAPSS, computes RUL from max_cycle - cycle) and .csv run-to-failure formats, producing health_index/vib_gearbox_rms/true_rul_hours. generate_calibrated_degradation_profile() synthesizes a NASA-style two-stage (linear-then-exponential) degradation curve as a static helper — used nowhere else in the read files (likely a data-generation utility for the ML training pipeline, not the live server).

What this is
A DRDO/iDEX (PS-26054) prototype: a digital twin and predictive health-monitoring system for the Rotax 912 iS Sport aero-engine used on Indian MALE UAVs (TAPAS-BH-201, Rustom-II). It's a single Python/TS/C# monorepo, not a game engine despite the folder name 3d_engine.

Architecture as designed vs. as actually built
The hub is real and solid. backend/server/main.py (FastAPI, port 8000) is backed by EngineStateService — a singleton running its own 20 Hz daemon thread (engine_service.py), independent of FastAPI's event loop. Each tick: synthetic telemetry generation (telemetry/can_streamer.py) → sensor sanity validation → 1D Otto-cycle physics residuals (physics/thermo_model.py) → a genuine 9-stage ML pipeline (ml/detection_pipeline.py: autoencoder+Z-score fusion, spectral/gearbox harmonic tracking, RF+heuristic fault classification, majority-vote debouncing, trend/RUL prognostics) → ATA-grounded diagnosis (agent/diagnostic_agent.py) → recorded into an in-memory mission graph → broadcast over REST (/api/state, /api/control) and two WebSockets (/ws/telemetry, /ws/blender) at 20 Hz.

Plane 2 (the "cognitive agentic/RAG layer") is built but orphaned. MissionCopilot and LocalKnowledgeStore (document loaders + FlashRank-or-keyword reranker, replacing a removed vector-RAG) exist and are unit-tested, but no server route ever instantiates them — there's no chat/ask endpoint. The "local LLM" support is detection-only (scans a llm/ folder that doesn't exist; never actually invokes a model). The "Interconnected Knowledge Graph" is a hand-rolled in-memory dict structure (not networkx, despite it being a declared dependency) with no persistence — it resets every server restart and lacks the Region/Environment/fleet-wide nodes the docs describe.

Only two clients genuinely talk to the backend: the React/TS web frontend (frontend/, schema-perfect match to backend/server/schemas.py, real WS+REST client, deployed via Firebase) and the Blender twin viewport (apps/blender_twin/standalone_digital_twin_app.py, via HTTP polling rather than its dedicated /ws/blender socket). The Pygame desktop GCS, the canyon flight sim, and the Unity bridge are all disconnected demos — they replay pre-baked frames or Perlin-noise-simulated telemetry with independently hardcoded fault catalogs, not live data from the server.

Known bugs/gaps worth knowing before touching code
Anomaly-event duplication: engine_service.\_tick() records a new graph anomaly/maintenance-action every 50ms tick a fault stays active (no debounce), producing duplicate rows in real mission reports and uncapped health-index decay.
Autoencoder weights (rotax_autoencoder.json) are missing from backend/ml/models/, so ae_score is always 0 in production.
RotaxFaultClassifier/RULEstimator are dead code, duplicated inline elsewhere.
Tri-source dataset fusion only fuses 2 of 3 sources (NASA data is parsed but never merged).
Unity's UnityDigitalTwinBridge.cs points at a nonexistent :8080/mcp endpoint.
